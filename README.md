# AI 视频助手

> macOS 原生 AI 视频创作工具 · Swift + SwiftUI + AVFoundation

[![Build macOS App](https://github.com/xiongliang1996/AI-Video-Assistant/actions/workflows/build.yml/badge.svg)](https://github.com/xiongliang1996/AI-Video-Assistant/actions/workflows/build.yml)

用一句话描述，让 AI 帮你把片子做出来。

---

## 功能

### 创作
- **AI 生视频** — 输入文字描述，调用 OpenAI 图像模型生成画面素材，风格 / 镜头运动可选
- **AI 配音** — 三引擎 TTS（OpenAI / Azure / 讯飞），多音色、可调语速
- **AI 字幕** — 两条路：Whisper 自动识别语音生成字幕（要 `verbose_json` 的**词级时间戳**，拆句后每条都卡在真实发音上；「整句 / 逐字」两种粒度，识别结果会按时间线片段自动换算时间）；或者把口播稿粘进来，**按标点自动断句 + 按语音停顿对齐时间轴**（离线，不需要 API Key）。配音已经在时间线上时可以直接选那个片段，不用再挑一次文件；对齐完可以逐条拖动时间码、±0.1 s 微调、吸附到最近的语音边界，也能整组平移，还能一键复原对齐结果；**导入 / 导出 SRT** 走标准格式，别人给的字幕直接拖进来就能用（UTF-8 / UTF-16 都认）

### 编辑
- 五轨时间线（V1 视频 / V2 画中画 / A1 音乐 / A2 配音 / S1 字幕），音频与视频都可上下拖动换层
- **画中画（V2 层）**：把素材拖到 V2 轨道，或把已有片段拖到第二层，它就缩成一个小窗浮在主画面之上。尺寸（10%–75%）、贴边留白、位置（四角 / 居中）都在属性面板里调；**也能直接在预览台上改**——按住画中画拖到任意位置，靠近四条边会自动吸附到留白线，**拖四角改尺寸**（对角固定、保持素材比例），双击回到九宫格位置。画中画保持素材自身比例，不参与「适应 / 填满」的裁切，也不做转场。缩放与不透明度关键帧照常可用（「缩放」在画中画上是尺寸的倍率）
- **画中画圆角 / 描边**：属性面板「外观」里调。圆角按短边比例算（0–50%，50% 就是正圆），四档预设「直角 / 小 / 大 / 胶囊」；描边同样是短边比例（0–8%），白 / 黑 / 品牌紫 / 暖黄四色，点颜色时如果宽度还是 0 会自动给一个看得见的最小值。两者都按比例存，换导出分辨率、改尺寸、缩放关键帧时不会变形——存像素的话 4K 项目在 1080p 预览里会圆得离谱
- **画中画投影**：同一组「外观」里的第三个滑杆，三档预设「关 / 轻 / 悬浮」。投影是**圆角形状的影子**，不是给矩形描一圈黑——改圆角时影子跟着变；模糊半径、深浅、偏移都按短边比例存，缩放关键帧时影子跟着一起放大缩小
- **调色**：曝光（±2 EV）、对比度、饱和度、色温（冷暖）四个滑杆，每条画面片段独立调，「还原」一键回到原样。参数存在片段上——复制片段会一起带走，转场、关键帧、画中画都不受影响；中性值（全 0 / 全 1）不触发逐帧合成，老项目成片逐像素不变
- **调色关键帧**：曝光 / 对比度 / 饱和度 / 色温都能打关键帧，从冷到暖、从灰到艳一次做出来。有关键帧时**拖滑杆改的是播放头那一时刻的关键帧**（没有就插一个）——静态值在有动画时根本不参与渲染，改它等于石沉大海；调色组标题旁会亮一个「动画中」标记
- **时间线拖拽**：拖动片段改位置，拖两端裁剪，自动吸附到相邻片段边缘 / 播放头 / 0 点
- **淡入淡出拖手柄**：片段上边缘两端各有一个圆点，拖它调淡入 / 淡出——音频调的是音量、画面调的是不透明度，片段上直接画出衰减区（暗色三角 + 包络线）。拖的时候头顶显示秒数，按 0.05 秒吸附；上限和渲染器一致（单侧最多片段时长的一半）。已经打了关键帧、或者入场转场生效时，那一侧的手柄会变虚并画成虚线——这两种情况下淡入淡出本来就不生效，先让你看见「拖了也没用」。右键可一键清除
- **时间线缩放**：`⌘=` / `⌘-` / `⌘0` 放大、缩小、还原，也可以用工具栏的滑杆；缩略图密度跟着缩放走，始终是「一格约 1.6 秒」的阅读节奏
- **素材拖入**：把素材面板里的文件直接拖到时间线任意轨道与落点，自动找最近的空位插入，同类轨道满了会顺延到下一层；拖动时跟着鼠标的是带缩略图的小卡片，不是系统默认的文档图标
- **悬停搓动预览**：鼠标在素材卡片上横向划过，画面跟着鼠标位置走（类似剪辑软件的 skim），底部有进度条、右上角有时间码；取帧异步执行，同一素材只保留最新一帧，鼠标快速划过不会堆过期请求
- **素材库整理**：按名称搜索（多关键词叠加、大小写与类型名都能命中）、按视频/音频/图片筛选、按导入顺序/名称/时长/类型排序（正倒序）、按类型分组平铺；自动统计每个素材被时间线用了几次，可一键筛出「未使用」并清理。清理只动素材库，不删磁盘文件
- **素材集合**：自己建文件夹式分组（口播 / 空镜 / 配乐…），一个素材可以同时属于多个集合；卡片右键即可加入或移出，也可以直接把卡片**拖到集合胶囊上**入组。集合胶囊上显示成员数。集合随项目一起保存，删除集合只解散分组、不动素材
- **集合内手动排序**：进集合自动切到「集合顺序」，卡片可以直接**拖动换位**（往下拖插到目标之后、往上拖插到目标之前，跟列表拖动的直觉一致），顺序写回集合并随项目保存；这时会强制平铺，避免分组打乱落点
- **真实波形**：读取音频采样（峰值 + RMS 混合）绘制包络，静音段与渐强段一眼可见；裁剪片段后包络跟着滑动，解码在后台线程并按文件缓存
- **多选批量操作**：`⌘` 点击增减选择、`⌘A` 全选，选中多个片段可整组拖动 / 一次性删除，属性面板显示片段数、时间跨度与总长
- **入场 / 出场动效**：六种预设（无 / 淡入 / 放大 / 左侧 / 右侧 / 下方），出场复用同一组方向反向播放（淡出 / 缩小 / 向左 / 向右 / 向下），各自独立时长 0.15–2s。**主画面和画中画都能用**——动效是片段自己的属性，把一段素材拖到 V2 就跟着它一起变成画中画动效，不用重设。动效是**叠在淡入淡出和关键帧之上的一层乘数**，所以已经打了缩放关键帧的片段照样能加一个淡入放大，两者相乘而不是互相覆盖
- **批量调色 / 外观**：多选后属性面板直接给出调色四滑杆 + 一键预设（原样 / 暖调 / 清冷 / 黑白），以及画中画的圆角 / 描边 / 投影。数值不一致的项显示「混合」，拖它就只改这一个分量——不会因为「拖曝光」把各片段自己的对比度、饱和度抹平。整批算**一步撤销**
- **时间线缩略图**：视频片段按宽度平铺源文件画面（异步取帧、按「文件 + 时间」缓存），裁剪后缩略图跟着入点走
- **智能剪辑**：分析配音停顿（20 ms 窗口 RMS → dBFS，阈值 / 最短停顿 / 最短语句可调），可「按停顿切片」或「删除停顿并前移」——后者是波纹删除，视频 / 音乐 / 字幕一起前移，音画不脱轨
- **真实转场**：交叉溶解、黑场过渡、左滑推入、缩放推入，导出与预览同时生效
- **转场体检**：属性面板直接告诉你这段转场「会不会生效」——相邻摆放、前一段素材还有没有尾巴、可用重叠够不够 0.12 s，5 种原因分类提示；有间隔 / 重叠时可一键「吸附到上一段」，`⌘⇧T` 批量吸附所有转场片段。时间线上生效的转场用白底角标 + 重叠区白色渐变标出，不生效的是橙色警示角标
- **素材重连**：文件在访达里被挪走或改名后，片段会黑屏。素材库顶部会提示「N 个素材找不到文件」，卡片上打红标；点「重连…」（`⌘⇧L`）把路径指回新位置就行——裁剪点、关键帧、转场、画中画参数全部保留，不用删掉重新导入。整个文件夹被挪走时选一次文件夹，按文件名批量匹配，一次修完；只认同名文件，改名猜不出来就不硬凑。导出前体检发现素材缺失时，面板底部也有「重连素材…」直通按钮
- **音乐自动闪避**：配音一响就把背景音乐压下去，说完再抬回来。选音乐片段点「自动闪避…」，**参考来源可以选「配音语音」或「字幕时间」**——前者分析另一条音频轨的波形，后者直接用字幕的显示区间（字幕本来就卡在发音上，更贴，还不用解码音频；标题卡那种文字图层不算）。它生成一条音量包络——强度（轻 / 中 / 重）、提前量、恢复时间、最短保留停顿都能调，右边有实时包络预览（阴影就是被压低的地方）。生成的是**普通音量关键帧**，之后还能在关键帧面板里逐点微调，不是黑箱。两句之间太短的停顿不会抬起来，否则音乐会来回抽搐
- **切割**：播放头处一键切开片段（`⌘` 工具栏剪刀按钮）
- **片段复制**：`⌘D` 把选中的片段整组复制一份，贴在整组末尾——属性、关键帧、画中画参数、转场全部带走；多选时保持相对间距；目标位置被占用就整组往右推，不会盖掉别的片段。右键菜单也有。没走 `⌘C` / `⌘V` 是故意的：macOS 的菜单快捷键优先于响应者链，绑了 `⌘C` 之后字幕面板的文本框就复制不了字了
- 片段属性：缩放、旋转、不透明度、音量、变速、淡入淡出、源入点、所属轨道
- **关键帧动画**：缩放 / 不透明度 / 音量 / 曝光 / 对比度 / 饱和度 / 色温可打关键帧（后四个只对画面片段开放），每段可选线性 / 缓入 / 缓出 / 缓入缓出；属性面板有曲线预览（带播放头竖线），导出与预览走同一套 ramp；转场区间里也会把关键帧叠加到转场进度上。属性选择器分两行——七个挤一行「不透明度」会被压成「不透…」
- **撤销 / 重做**：`⌘Z` / `⇧⌘Z`，拖拽与滑杆按操作合并成一步
- **项目持久化**：自动保存到 `~/Library/Application Support/AIVideoAssistant`，支持导出 `.aiva` 文件
- **字幕烧录**：字幕 / 文字真正画进画面（字号、颜色、底衬、距底位置、粗体），预览与成片同款样式
- AVFoundation 编码导出（H.264，720p–4K）；无字幕走硬件编码，有字幕走逐帧绘制
- **导出预设**：内置横屏 1080p / 4K / 60fps、竖屏 1080 / 720 草稿、方形 1080 六套参数，点一下整套切换；也能把当前参数存成自己的预设（重名自动加序号）。画幅填充可选「适应（留黑边）」或「填满（裁切）」，竖屏交付不用再去别的软件里改
- **导出队列**：`⌘E` 入队、串行执行，排队期间可以继续剪；`⌘⇧E` 看进度、取消（取消会清掉写了一半的文件）、在访达里定位成品
- **仅导出音频**：`⌘⌥E` 或工具栏的「仅音频」，只出混好的 M4A——播客 / 口播交付只要声音时不用渲染画面。它和视频导出共用同一个队列，音量包络、淡入淡出、变速都照常算进去；时间线上没有声音会明确报错，不会给你一个空文件
- **导出前体检**：点导出先扫一遍时间线，把「能导出、但成片不是你要的」问题列清楚——素材文件丢了、片段比素材长、转场不会生效、同轨重叠、字幕跑到片尾之后或显示太短、画幅和成片比例不一致、画面空隙会变黑场、画中画下面没有主画面或小到看不清。按严重程度分三级，能直接「仍然导出」
- **通用二进制**：一份 `.app` 同时带 arm64 与 x86_64，Intel Mac 和 Apple Silicon 都不用另找版本
- **可查的日志**：所有关键动作和失败原因同时写进 `~/Library/Logs/AIVideoAssistant/app.log`（超过 512 KB 自动滚一份旧的），设置 → 关于里有「打开日志文件」。素材读不出时长、项目文件坏了、导出失败、AI 接口报错都会留下 HTTP 状态码和服务端原话，出问题不用靠猜

## 安装

### 方式一：下载构建产物

1. 打开 [Releases](https://github.com/xiongliang1996/AI-Video-Assistant/releases/latest) 页面
2. 下载 `AIVideoAssistant-macOS.zip`，解压后把 `AI视频助手.app` 拖进「应用程序」

> **说明**：产物是 **通用二进制（arm64 + x86_64）**，Intel Mac 和 Apple Silicon 都是原生运行，不需要 Rosetta。CI 跑在 `macos-15-intel` 上，用两个架构各编一遍再 `lipo` 合成。

### 首次打开被系统拦住怎么办

应用是 **ad-hoc 签名、没有做公证**（Apple 开发者账号每年 $99，个人项目先省了），所以 macOS 会说「无法验证开发者」或直接把图标划一道杠。三个办法任选一个：

1. 右键（或 Control-点击）图标 → **打开** → 弹窗里再点「打开」。之后就不会再拦。
2. 打开「系统设置 → 隐私与安全性」，页面下方有「仍要打开」按钮。
3. 命令行去掉隔离标记（最省事）：

```bash
xattr -dr com.apple.quarantine "/Applications/AI视频助手.app"
open "/Applications/AI视频助手.app"
```

这是 Gatekeeper 对「未知开发者」的默认行为，不是应用本身有问题——源码都在这个仓库里，可以自己 `./scripts/build-app.sh` 编一遍再跑。

### 方式二：从源码构建（原生架构）

```bash
git clone https://github.com/xiongliang1996/AI-Video-Assistant.git
cd AI-Video-Assistant/AIVideoAssistant
./scripts/build-app.sh release
open dist/AI视频助手.app
```

环境要求：macOS 13+、Swift 5.9+（Xcode 或 Command Line Tools）

## 配置 AI

启动后按 `⌘,` 打开设置：

| 能力 | 需要的凭证 |
|------|-----------|
| AI 生视频 / 字幕识别 / OpenAI 配音 | OpenAI API Key |
| Azure 配音 | Azure Speech Key + 区域 |
| 讯飞配音 | AppID + APIKey + APISecret |

凭证保存在 macOS 钥匙串，卸载应用前可用设置页的「测试连接」验证可用性。

## 隐私

一句话：**素材不上传，只有你主动用 AI 功能时才会联网。** 应用内「帮助 → 隐私说明」有同一份说明。

| 事项 | 具体情况 |
|------|---------|
| 素材与项目 | 只在本机解码、合成、导出，不上传、不统计、不需要登录 |
| AI 生图 | 把**提示词**发给 OpenAI（`/v1/images/generations`） |
| AI 配音 | 把**文本**发给所选服务商：OpenAI / Azure / 讯飞 |
| Whisper 转写 | 把**音频片段**发给 OpenAI（`/v1/audio/transcriptions`） |
| API Key | macOS 钥匙串，项目文件与日志里都没有明文 |
| 日志 | `~/Library/Logs/AIVideoAssistant/app.log`，记录时间 / 操作 / 错误，含文件路径，不含素材内容；可随时删除 |

不用 AI 功能时，应用不发起任何网络请求（除了你在设置里点「测试连接」）。

### 素材库检索规则

搜索框里的内容按空白切分，**每个关键词都要命中**才算匹配（AND），所以「采访 01」只会留下同时含这两个词的文件。匹配范围是文件名（含扩展名，所以打 `mp4` 能筛出所有 mp4），另外关键词**恰好等于**类型名（`视频` / `video`）时按类型匹配——只认全等，避免打一个 `a` 就把所有 audio 都匹配出来。

排序是稳定排序：按「时长」或「类型」排序时，值相同的素材保持导入顺序，切换正序 / 倒序也不会让等值项互相换位。

集合和类型、搜索、未使用这几个条件是**叠加**的（先按集合取成员，再叠其它条件），集合胶囊上的数字也只算素材库里还在的成员，陈旧 id 不会虚报。

「已用 ×2」这类角标来自 `MediaShelf.usage(in:)`：优先用片段的 `assetID` 对，老项目里没存 `assetID` 的再退回按文件路径对。所以清理未使用不会误删正在被时间线引用的素材。

### 集合怎么存

集合写在项目文件的 `collections` 字段里（`{ id, name, assetIDs, createdAt }`），成员存的是**素材 UUID**。这带来一个必须处理的问题：素材的 UUID 原本是每次启动重新生成的，那样集合成员和片段的 `assetID` 全都会对不上。所以 `MediaAsset` 改成可以从文件恢复 id（`MediaAsset(url:id:)`），加载项目时沿用文件里的 UUID。

`ProjectSnapshot` 换成了自定义 `init(from:)`，`collections` 用 `decodeIfPresent` 兜底——v1.12 及更早写出的项目文件没有这个字段，照样能打开，只是没有集合。素材被移出素材库时，集合里的成员会同步清理（`MediaShelf.sanitized`），避免留下指向不存在素材的残影。

### 集合内怎么排

选中集合时排序方式会切到「集合顺序」，直接读 `MediaCollection.assetIDs` 的次序。拖动卡片时走 `MediaShelf.reorder(ids, moving:over:)`：**向下拖插到目标之后、向上拖插到目标之前**，和 Finder / 列表里「插入线跟随拖动方向」的手感一致；拖到自己身上、拖到不存在的目标都原样返回，不会把顺序搅乱。判断依据是移动前后的索引关系（`from <= anchor` 决定插到前还是后），所以「交换两次能回到原序」这种往返操作也不会漂。

这时会强制平铺（分组会把落点打乱），分组按钮置灰。想按类型分组看，切回别的排序方式即可——集合顺序本身不受影响，因为它存在 `assetIDs` 里而不是显示顺序里。

拖到集合胶囊入组也复用同一条 `fileURL` 通道：卡片拖出去带的是文件 URL（时间线也认这个格式），落点上用 `MediaShelf.assetIDs(forURLs:in:)` 反查素材库——同时比对标准化路径和解析过符号链接的路径，所以 `/var` 与 `/private/var`、`/tmp` 与 `/private/tmp` 这两种写法都能对上。拖进来的文件不在素材库里时给提示而不是静默丢弃。

### Whisper 字幕为什么能卡在发音上

以前只拿 SRT：那是**句级**时间，一句 20 多字的口播烧到画面上就超出安全区；想拆成两条，只能按字数瞎猜时间。现在请求 `response_format=verbose_json` + `timestamp_granularities[]=word`，拿到每个词的真实起止（`words`），拆句之后每一条的时间都来自真实发音。

| 分段方式 | 怎么分 | 时间从哪来 |
|---|---|---|
| 整句 | 攒词，放不下（视觉长度 > 18）或碰到句末 / 句中标点且已经够长（≥ 6）就收一条 | 首词起点 → 末词终点 |
| 逐字 | 一个词一条；纯标点不单独成条，并进上一条并把结尾拉长 | 该词自己的起止 |

英文的词自带前导空格（`" world"`），拼的时候原样接上、只在收尾 trim，否则 `Hello world.` 会粘成 `Helloworld.`。

两层兜底：服务端不认 `verbose_json`（常见于兼容代理）时自动退回 SRT 再解析一次；能解析但没给 `words` 时，退回「把过长段落重新断句 + 按发音权重在原区间里分配时间」——比按字数平均准，因为英文单词的权重更高。

选的是时间线片段时，只保留 `[sourceStart, sourceStart + duration)` 窗口内的字幕，再整体平移到片段位置，最后统一过一遍 `SubtitleTiming.sanitized`（不早于 0、不越总时长、不压邻居、单条不短于 0.1 s）。识别完界面上会交代一句：几条字幕 · 词级时间戳多少个 · 用的哪种粒度。

### 文稿怎么变成字幕

「文稿对齐」不需要 API Key，全离线：断句用规则，时间靠音频停顿。

**断句**（`SubtitleBreaker`）。长度按「视觉长度」算：一个汉字算 1，一个 ASCII 字符算 0.55，所以 `maxLength = 18` 表示 18 个汉字或约 33 个英文字母，英文不会因为字母多被判成超长。顺序是：先按手动换行切段 → 按句末标点（`。！？；…`）切句 → 按句中标点（`，、：—`）切小句 → 贪心装箱到上限。破折号也算断点，否则「——」会被硬切劈成两半。

上限是**软**的，允许溢出约 25%：中文没有空格，硬切必然切断词语，为了两个字把一句话劈开比略超更难读。只有超过 1.2 倍才硬切，而且切得**均匀**（22 字切 11+11，不是 18+4，否则尾巴会短到没法看）。切完做两道后处理：太短的条并到相邻条（合并后不能超过 1.05 倍上限），以及避头尾——标点不能出现在行首，开引号 / 开括号不能留在行尾。

**对齐**（`SubtitleAligner`）。先跑 `SilenceDetector` 拿到语音 / 停顿区间，然后分三种情况：

| 情况 | 做法 |
|---|---|
| 语音段数 == 句子数 | 一一对应，最准。一句一停的配音基本都是这种 |
| 段数不一致 | 按发音权重（汉字 1、英文单词 1.6）把句子铺在「所有语音区间首尾相接」的压缩时间轴上，再映射回真实时间——所以字幕不会盖住停顿 |
| 检测不到语音 | 按总时长均分，只当可调的初稿，界面上会明确警告 |

之后统一做三件事：相邻空隙小于 0.3 s 就补上（避免字幕闪一下）、保证不重叠、把每条夹在 `[minDuration, maxDuration]` 里。空间实在不够时（多条字幕挤在极短的语音里）**不重叠优先于最短时长**。

对齐完会给一份体检报告：是不是一句一停、平均每条多少秒、句数对不上时提示可能有偏差。

### 配音已经在时间线上怎么办

不用再选一次文件。素材区下面会列出时间线上的音频片段，点一下就当配音用。区别在于**时间基准**：文件里的第 1 秒不一定等于时间线的第 1 秒——片段可能被裁过（`sourceStart`），也可能不从 0 开始（`startTime`）。所以分析完要先把「文件时间」映射成「时间线时间」：

```
时间线时间 = 片段起点 + (文件时间 - 片段入点)
```

只保留 `[sourceStart, sourceStart + duration)` 这个窗口里的语音，窗口外（被裁掉的头尾）的语音直接丢弃——那些地方的字幕本来就不该出现。这一步是 `SubtitleAligner.remap`，纯函数。

### 时间对得不完美怎么调

列表里每一行的时间码本身就是拖动把手：点一下选中，左右拖动整体平移（0.05 s 一档）。选中后列表底部出现微调条，可以按 0.1 s 前移 / 后移，或者缩短 / 加长结尾，右侧实时显示这一条前后还剩多少空隙（`前 0.5s · 后 0.5s`），心里有数不会白按。

对不准的时候还有两条更快的路：

- **吸附到语音**（`SubtitleTiming.snapToSpeech`）：起点吸到最近的语音起点、结尾吸到最近的语音终点，容差 0.35 s。不做「起点也能吸到语音终点」这种双向吸附——那会把字幕拉进停顿里，看着像提前出场。容差外的边界一律不碰，免得一句话被拽到老远。也可以「全部吸附」，逐条往后处理，后一条看到的是前一条吸完的结果，所以不会互相压住。
- **整组平移**（`shiftAll`）：全部条一起挪 0.1 s，处理「字幕整体比画面早半秒」这类系统性偏差。整块一起动，所以组内不会产生新重叠，只夹住两头不越界。

所有改动都走 `SubtitleTiming`，守三条硬规则：

| 规则 | 原因 |
|---|---|
| 不早于 0、不越过总时长 | 出界的字幕在成片里根本不显示 |
| 不压到前一条结尾、不盖住后一条开头 | 字幕一叠就是两行字糊在一起，比时间略偏更难看 |
| 单条不短于 0.1 s | 再短就只是闪一下 |

总时长只算非字幕片段（视频 / 音频 / 文字）——如果把字幕自己也算进去，最后一条就永远没法往后拉了。改完可以点「复原对齐」把时间退回刚对齐完的样子，文本编辑保留。

### 导出预设怎么算的

一套预设就是分辨率 + 帧率 + 画质 + 画幅填充四项。内置六套：横屏 1080p、横屏 4K、横屏 60fps、竖屏 1080、竖屏 720 草稿、方形 1080。

匹配是**全等**匹配：四项都一致才算「当前用的是这个预设」，改任何一个参数就显示「当前是自定义参数」。这样不会出现「明明改过却还高亮着某个预设」的误导。内置预设用固定 UUID，所以重启后「当前预设」还认得出是哪一个。自定义预设存在 `~/Library/Application Support/AIVideoAssistant/export-presets.json`，读回来时会剔掉混进来的内置预设，避免出现两份同名胶囊。

**画幅填充**决定素材比例和画幅不一致时怎么办：

| 方式 | 缩放比例 | 效果 |
|---|---|---|
| 适应 | `min(宽比, 高比)` | 完整画面，短边方向留黑边 |
| 填满 | `max(宽比, 高比)` | 铺满画幅，长边方向被裁掉 |

16:9 素材进 1080×1920 竖屏：适应是 0.5625（上下各留 656px 黑边），填满是 1.7778（左右各裁掉约 45%）。

顺带修掉一个隐藏很久的问题：**未覆盖区域会编出绿色**。AVFoundation 的合成器不会清空画幅里没有画面覆盖的部分（时间线空隙、适应模式的黑边），那些像素来自未初始化内存，编出来是 YUV(0,0,0) 对应的绿色——某些分辨率下恰好是黑的，所以一直没被发现。现在合成时会垫一条铺满全片的黑色底轨（一帧黑色画面按总时长拉伸，60 秒的时间线也只插一次），留白才是真黑。

### 导出前体检查什么

这些问题的共同点是：**不会让导出报错**，成片出来才发现，改一轮就得重导一遍。

| 级别 | 查什么 | 观众会看到 |
|---|---|---|
| 会出错 | 素材文件找不到 / 没指向文件 / 读不出时长 | 这一段直接缺失 |
| 会出错 | 时间线上没有视频片段 | 导不出画面 |
| 注意 | 片段比素材可用长度长（含倍速） | 自动截短，后面露出黑场 |
| 注意 | 转场不会生效（复用属性面板那套 5 类诊断） | 该转场的地方是硬切 |
| 注意 | 同轨片段重叠 | 重叠部分被前一段盖住 |
| 注意 | 字幕在片尾之后 / 显示不足 0.3 s / 两条叠在一起 | 看不到、来不及看、糊成一团 |
| 提示 | 素材比例和画幅不一致 | 适应留黑边 / 填满被裁（按当前填充方式给不同建议） |
| 提示 | 画面空隙超过 0.5 s | 渲染成黑场 |

成片时长只算视频和音频——把字幕自己也算进去的话，片尾之后的字幕就永远查不出来。素材时长和画幅用 `AVURLAsset` 读一次（同一路径只读一次，音频不读画幅），所以体检是异步的；没有问题时不会多一步，直接进保存面板。

`PreflightCheck.inspect` 把素材信息当参数传进来，不碰磁盘也不碰网络，所以断言能直接喂合成数据跑。

### 转场是怎么实现的

时间线片段交替落在 A / B 两条视频轨道上。给片段设置转场时，前一个片段的素材**向后多取 t 秒**（需要素材本身还有余量，没有就自动缩短或跳过），后一个片段按自己的入点正常开始，于是两段在 `[后片入点, 后片入点 + t]` 区间重叠。合成指令在这个区间里同时挂上两条轨道的图层指令：

| 转场 | 实现 |
|------|------|
| 交叉溶解 | 前段不透明度 1→0，后段 0→1 |
| 黑场过渡 | 前半段前片淡出到黑，后半段后片从黑淡入 |
| 左滑推入 | 两段做平移变换 ramp |
| 缩放推入 | 后段 0.86→1.0 缩放 + 淡入 |

### 转场什么时候会失效

上面这套机制有 4 个隐含前提，缺一个就不会生成转场指令（画面直接硬切）。以前界面上没有任何提示，很容易误以为渲染坏了；现在属性面板会直接报出是哪一条不满足：

| 状态 | 原因 | 怎么办 |
|------|------|--------|
| `gap` | 与前一段之间有间隙（容差 0.06 s） | 一键「吸附到上一段」 |
| `overlap` | 与前一段重叠摆放，两段同时占位 | 一键「吸附到上一段」 |
| `noTail` | 前一段的素材已经用尽，没有尾巴可吃 | 把前一段右边缘往回缩一点 |
| `tooShort` | 算出来的重叠不足 0.12 s | 两段留长一些 / 多留尾巴 |
| `noPrevious` | 前面没有片段 | 挪到某段后面 |

诊断函数 `TimelineLayout.transitionStatus` 与 `CompositionBuilder` 的判定逐条对齐，测试里用真实素材把「诊断说生效」和「合成器真的产出两层图层指令」做了交叉验证。

### 转场导出报 `-11841` 是怎么回事

AVFoundation 对视频合成指令（`AVVideoCompositionInstruction`）有个硬要求：所有指令必须**首尾相接、互不重叠、并且严丝合缝铺满整个合成时长**。哪怕最后只差一个 tick（1/600 秒）没盖住，整个 composition 就判为非法，导出直接失败：

```
The video could not be composed. (AVFoundationErrorDomain -11841)
```

以前指令的起点、终点、长度是各自独立取整的：`CMTime(seconds: start)` 取一次、`CMTime(seconds: to)` 取一次、`CMTime(seconds: to - from)` 又取一次。三次独立取整在对不齐时会差出 1 个 tick，于是出现两种症状：

- **漏一格** → 指令没铺满整片 → 导出 `-11841`。表现为重叠时长 0.12 / 0.13 / 0.14 秒必挂，0.15 秒却正常，看起来像「某些转场时长有 bug」
- **叠一格** → 同一图层上两条不透明度 ramp 相交 → AVFoundation 直接抛异常 `The timeRange of an opacity ramp must not overlap the timeRange of an existing opacity ramp`

还有个更隐蔽的：`CMTime(seconds:preferredTimescale:)` 是**截断**而不是四舍五入，3.01 秒 × 600 = 1805.9999… 会被截成 1805，于是黑底轨、合成时长、最后一条指令各差一格。

现在统一成三条规则：

1. 所有「秒 → CMTime」都走 `CompositionBuilder.cmt()`，四舍五入到最近的 1/600 秒
2. 区间长度一律由两端相减得出（`CMTimeSubtract(end, start)`），不再单独取整
3. 指令用「铺砖」方式生成：每条新指令都从上一条的结尾开始，缝隙补黑场、重叠裁掉；收尾再夹到合成时长，保证首条从 0 开始、末条正好结束在片尾

验证走的是「真导出 → 读回文件取帧」：30 / 24 / 60 fps、整帧与非整帧起点、四种转场、关键帧分段路径、时间线空隙、4:3 素材进 16:9 黑边、竖屏填满、带配音，26 例导出全部通过（修复前 0.12 / 0.13 / 0.14 秒在三种帧率下全部失败）；另有 2111 条不变量断言（7 组固定用例 + 150 条随机时间线）确认「指令严格铺满 `[0, 合成时长]`」。

### 画中画为什么要把不透明度压到 0

画中画是「一条独立视频轨 + 在合成指令里多挂一层」。第一版实现很自然会想到：只在画中画的时间段里给它挂图层指令，时间段外不挂。实测不行——**AVFoundation 对断流 track 的处理是把最后一帧一直 hold 到指令结束**，于是画中画从自己的结尾开始「冻」在屏幕上，一路糊到片尾。

换一个思路：指令**一条都不切**，画中画图层挂在所有「与它区间相交」的指令上，但不透明度曲线做成「区间外 0 / 区间内按自身属性走」。hold 住的就成了透明帧，画面干净，而且主画面的指令、转场 ramp、关键帧分段全部原封不动——画中画横跨转场区间也不会把指令切碎。

曲线按折点采样：片段两端、淡入淡出边界、关键帧时间点。指令如果从曲线中间切开（比如转场把画面切成两段），端点值按线性插值算出来再发 ramp，所以跨指令不会跳变。区间前把图层显式压到 0（否则默认是不透明的），区间后补一个归零台阶。

几个实测确认过的边界：

| 场景 | 结果 |
|---|---|
| 画中画边界不落帧（1.01–1.99 @30fps） | 1.00 底 / 1.05 画中画 / 2.00 底，边界精确 |
| 画中画贴到片尾 | 一路到底，不多 hold 也不提前断 |
| 带淡入淡出 | 区间内出现中间混色，两端仍是底 |
| 只有 0.03 s（不到 1 帧） | 只在该帧出现 |
| 画中画横跨转场 | 导出正常，画中画始终在最上层 |
| 时间线上只有画中画、V1 全空 | 补一条全黑底指令兜住，背景是真黑不是绿 |

> 顺带踩到一个坑：只有画中画时一条主画面指令都不会生成，`vc.instructions` 为空 → 又是 `-11841`。所以生成完要先判空补一条黑底指令，再走「铺砖」的收尾逻辑。

### 圆角为什么要自己写合成器

`AVMutableVideoCompositionLayerInstruction` 只支持「变换 + 不透明度」，没有任何遮罩能力。想给画中画做圆角，只有三条路：

1. **把圆角烘进源素材**——重新编码一遍画中画，画质二次损失，改一次参数重编一次，预览根本跟不上；
2. **`AVVideoCompositionCoreAnimationTool`**——macOS 26 上渲染全白，字幕就是因为这个才改成自绘的；
3. **自己实现 `AVVideoCompositing`**——接管整帧合成，用 CoreImage 逐帧画。

选了第三条，但把范围卡死：**只有项目里真的设了圆角 / 描边时才挂这个合成器**（`PiPStyle.hasDecoration`）。全直角的项目继续走系统合成器，那条路有几百条断言兜着，没必要为了「没开这个功能」的项目换引擎。

自绘路径没有重写「铺砖」逻辑，而是把系统已经铺好的指令**逐条翻成自绘指令**：指令边界、转场区间、空隙补黑这些规则在 `makeVideoComposition` 里已经调通过（踩过 `-11841`），重排一遍等于把那些坑再踩一次。转换时只补「每层在这一段里的曲线」。

曲线**不重新写一份**。转场的两层状态抽成了 `transitionState(transition:prev:cur:renderSize:start:duration:at:)`，系统路径拿它喂 `setOpacityRamp` / `setTransformRamp`，自绘路径拿它采点。各写一份迟早漂移——「预览看着没问题、导出少淡一格」这种 bug 最难查。

坐标系要翻一次：AVFoundation 的视频坐标原点在左上、y 向下；CoreImage 原点在左下、y 向上。套变换之前先做 `(0, H) 平移 + y 翻转`，输出前再翻回来。

装饰放在**源画面空间**做，不是画布空间。有缩放关键帧时，源空间裁一次就够，圆角会跟着一起放大缩小，符合直觉；在画布空间做就得每帧反推画中画矩形，还得处理旋转，容易算错。

验证方式是**等价性比对**：同一组时间线（两段 + 交叉溶解 + 画中画）跑两遍，一份直角走系统合成器、一份圆角走自绘合成器，在 5 个时刻（片头淡入后 / 片尾 / 转场起点 / 转场中点 / 第二段）× 4 个探针逐点比对画中画以外的像素，差超过 4% 就失败。这个测试第一次跑就抓到一个真 bug：转场时前一段的「延展时长」没算进区间相交判定，导致前一段被漏掉，交叉溶解直接变成硬切。

### 入场动效为什么不做成关键帧

最直觉的做法是「点一下预设，就往片段里插三组关键帧」。问题是用户已经手打过缩放关键帧时，预设要么覆盖掉、要么和已有的打架，最后得到一条谁也看不懂的曲线。

所以动效是**独立的一层乘数**：渲染时先按原来的规则算出「不透明度 + 变换」（淡入淡出、关键帧、缩放全照旧），再乘上动效给的三个系数（透明度、缩放、位移）。两者天然可以共存，动效也不需要出现在关键帧面板里。

四个容易错的点：

**采样点必须细分。** `setOpacityRamp` / `setTransformRamp` 在两点之间是线性的，而缓出曲线（`1-(1-p)³`）不是。只取动效窗口两端，整段会变成匀速滑入，起手的「快」全丢了。每个窗口补 8 个点，0.6 秒的动效大约 0.075 秒一个采样。

**出场用同一条曲线反向。** 进度从 1 掉到 0 时，同一条缓出曲线读起来就是「越走越快」地离开，正好符合观众对退场的预期，不用再写一套。

**位移按画中画自身宽高换算。** `dx = -1` 表示「左移一个自己那么宽」，而不是一个固定像素值——这样同一套参数在 1080p / 4K、在 32% 宽和 60% 宽的画中画上表现一致。

**时长要夹到半个片段内。** 入场 2 秒 + 出场 2 秒，配一个 3 秒的片段就会互相踩。夹到半段之后两个窗口永远不重叠，中段一定是「就位」状态。

动效**不需要换合成引擎**：系统合成器那条路本来就在发 opacity / transform 的 ramp，动效只是把系数乘进去。所以加了动效的导出耗时和没加基本一样，只有圆角 / 描边 / 投影 / 调色才需要走自绘管线。

验证分两层：先断言曲线本身（起点全透明、终点归位、中点已经过半 = 缓出、缩放绕中心、位移换算），再真导出量像素——淡入的开头中心接近底色、1.2 秒后是画中画本色；左侧滑入的开头中心还没有画中画；出场末尾淡回底色。

### 主画面动效为什么单独走一条 layerInstruction

动效最初是挂在 `PiPStyle` 上的（画中画专用），因为那时候只有画中画会缩成小窗浮在上面。主画面要加同一个「淡入放大」时，第一反应是「给它也塞一套同样的字段」——但那就成了两份实现，曲线、时长夹取、采样密度迟早漂移。

所以动效被提到**片段级**（`ItemProperties.motion`）。画中画只是「一个恰好有自己矩形的片段」，动效本身不该关心自己贴在哪一层。老项目里存在 `pip` 容器下的那四个字段，解码时搬一次家（`LegacyMotionKeys`），用户不用重新设置。

渲染侧两条路径分开了：

**自绘路径**（有圆角 / 调色时才走）不用改结构——`mainLayerSpec` 本来就逐时刻求值，`opacity(at:)` 和 `transform(at:)` 各乘一个系数就行。

**系统路径**要麻烦些：它本来给每个片段发**一条** `AVMutableVideoCompositionLayerInstruction`，整段只有一个 opacity ramp 和一个 transform ramp。动效要求在片段**内部**再多切出几个窗口（入场、出场），所以主画面走 `motionLayerInstruction`：先收集所有断点（片段两端、淡入淡出边界、缩放 / 不透明度关键帧、动效采样点），去重排序后逐段发 ramp，段首先落一个定值避免首帧跳变。

三个容易踩的点：

**位移的单位不一样。** 画中画的 `dx = -1` 是「左移一个自己那么宽」，主画面没有「自己那么宽」这个概念（它铺满画幅），所以主画面按**画幅**宽高算（`rect = CGRect(origin: .zero, size: renderSize)`）。同一个预设因此在两种片段上都是「移出画面」，观感一致。

**不能借 `pipGeometry` 复用变换。** 那个函数是按画中画比例反算矩形的，主画面传进去会被缩成一个小窗。主画面自己的基准变换是「缩放 + 旋转绕中心」，动效只往上乘。

**转场区间必须让位。** 相邻两段之间有交叉溶解时，前一段的指令会被延展到转场结束，动效窗口要是也铺过去就会和转场进度抢同一段不透明度。所以转场生效时，动效在转场起点就收住——测试里对转场区间逐点比对，加了动效前后最大差 `0.000`。

验证是 34 条断言：默认不动效不换引擎、四种入场 + 出场真导出量像素、和淡入叠加、和缩放关键帧共存、转场区间让位、自绘路径一致、相邻片段、以及 50 次合成构建耗时（0.044 秒，动效没有引入可感知的构建开销）。

### 批量编辑为什么传的是「改一个分量」而不是整个调色

多选时几个片段的其它参数往往并不相同：A 是 `对比度 1.3 / 饱和 0.7`，B 是 `0.9 / 1.4`。如果批量接口收一个完整的 `ColorGrade`，用户只想统一曝光，就得先决定「另外三个分量取谁的值」——取谁的都错，结果是把别人辛苦调的对比度抹平。

所以接口收的是**逐分量闭包**（`(inout ColorGrade) -> Void`），滑杆只写自己那一个字段，预设才整组赋值。界面上对应的就是「数值不一致时显示混合」，拖它只动这一个分量。

两个配套的规矩：

**带调色动画的片段被跳过，不硬写。** `animatedValue` 一旦发现这个属性有关键帧就完全不看静态值，批量写静态值等于「点了没反应」。面板会把「N 个片段带调色动画，已跳过」写出来，并给一个单独的「清掉这些片段的调色动画」按钮——清的时候把**播放头那一帧**的颜色留下来当静态值（播放头在片段外就取最近的一端），画面不会突然跳回原色。

**整批只压一次撤销快照。** 一次批量改 10 个片段，撤销一步就该全回来，而不是按 10 次。反过来，值没变化时（比如点了个当前就是的预设）不压快照，免得撤销栈被空记录塞满。

批量外观只对画中画开放：主画面铺满画幅，圆角裁出来只会得到四个黑角。

### 调色关键帧为什么要写到播放头

调色的四个分量和缩放 / 不透明度不一样：它们**同时**参与一帧的合成，而 `animatedValue` 一旦发现有这个属性的关键帧，就完全不再看静态值。所以「有关键帧时改滑杆」如果还去写静态值，用户拖动会看到画面纹丝不动——参数确实存进去了，只是没人读它。

界面层的解法是把绑定拆开：`gradeBinding` 的 `get` 读的是**播放头这一时刻的有效值**（`resolvedGrade(at:)`），`set` 在有关键帧时把新值写进播放头所在的那个关键帧（0.05 秒内算同一帧，没有就插一个）。这样拖滑杆 = 直接改这一时刻的画面，和「在关键帧列表里调值」是一回事，只是少点两下。

合成侧的采样点不能只取关键帧端点。缓动（缓入 / 缓出 / 缓入缓出）会让曲线在段内是非线性的，只采端点再线性插值就把缓动丢了。所以时间点直接取 `animationSamples` 的结果——那个函数本来就在给缩放 / 不透明度做缓动细分（每 0.06 秒一个点），复用它，调色和几何动画的曲线形状自然一致。

还有一个细节：`needsCustomCompositor` 必须把「有调色关键帧」也算进去。只看静态值的话，一个中性调色 + 曝光动画的项目会走系统合成器，导出成片完全不调色——断言里「打了关键帧就挂自绘合成器」就是防这个。

### 投影为什么要自己算形状

现成的 `CIShadow` 用不了：它的阴影形状取**输入图的 alpha**，而视频帧的 alpha 永远是满的，投影会变成整块矩形——圆角白做了。

所以投影复用圆角裁切的那一个遮罩（`CIRoundedRectangleGenerator`），走「遮罩 → 偏移 → 高斯模糊 → 染成影子色 → 乘不透明度」。四个地方容易错：

**顺序不能反。** 投影必须垫在**裁完圆角之后**。`decorate` 里的 `CISourceInCompositing` 会把 extent 收回到画面矩形，先垫阴影会被那一步直接裁掉，表现为「参数都设了但导出看不见影子」。

**模糊后的 extent 是无限的。** `CIGaussianBlur` 输出没有边界，不 `cropped(to:)` 裁回扩展矩形，后面整条管线都在无限画布上跑，导出会卡死或直接失败。

**偏移方向要翻。** 参数存的是「视频坐标、y 向下为正」（用户理解的「往下投」），进合成器要翻成 CoreImage 的负 y。翻错的表现是影子跑到画中画上面去。

**扩展量要够。** 模糊大约 3σ 之外就衰减没了，留 `blur × 2.5 + |offset| + 2` 的余量，否则阴影边缘会被硬边切一刀。

验证分两层：先用静态渲染断言「圆角处阴影收进去、同样条件下直角填满角落」（这一对是控制变量，只测一个说明不了形状对不对），再真导出量像素——画中画下方必须比上方暗（证明偏移生效）、画中画本体像素与「不开投影」逐点一致（证明投影只是垫在下面、没动本体）。导出耗时 0.21s → 0.22s，加投影几乎不要钱。

### 调色的两个反直觉点

调色走的是同一条自绘管线（先调色、再裁圆角——描边是用户挑的颜色，不该被调色带偏），但 `CIColorControls` 和 `CITemperatureAndTint` 各有一个方向问题和直觉相反：

**色温是反的。** `CITemperatureAndTint` 的 `inputTargetNeutral` 调高，画面会变**冷**而不是变暖——它的语义是「这段素材是在这么冷的光下拍的」，补偿出来自然偏蓝。所以滑杆 +1（更暖）要算成更低的 target 色温：`6500 − value × 2600`。这个方向是实测出来的，第一次跑断言时两条都反了。

**对比度在线性空间作用，不在 sRGB 空间。** 中灰 0.608（sRGB）换算到线性只有 0.33，所以「对比度 0.5 会让中灰更靠近 0.5」这个直觉是错的——它把 0.33 拉向 0.5，sRGB 上反而更亮。验证对比度必须拿**一亮一暗两块素材**分别测「亮暗差是拉开还是压缩」，单看中灰会得出相反结论。

### 画中画在预览台上怎么拖

位置存的是**归一化坐标**（左上角在画幅里的 0–1 比例），不是像素。换导出分辨率不用重设，这也是九宫格那套参数本来的做法。`freeOrigin` 为 `nil` 时按九宫格贴边，所以点一下九宫格就能把拖歪的画中画拉回整齐位置。

坐标换算有三个必须踩对的点：

**预览框有黑边，不能拿视图尺寸当画幅。** 预览台是 `AVPlayerLayer` + `resizeAspect`，成片比例和预览框比例不一致时会留黑边。所有换算都先过一遍 `fittedRect(contentSize:in:)` 求出真正的画面矩形，否则画中画会跟着黑边一起漂。

**拖动要按中心点反算。** 手势抓的是画中画的中心，如果拿左上角去加位移，按下的瞬间画中画会往右下跳半个身位。所以先记下按下瞬间的中心点，位移换算成归一化增量，再反推左上角。

**拖动期间不写盘。** 每次写回都会重建预览合成（一次完整的 `CompositionBuilder.build`），边拖边写会卡成一帧一帧。所以拖动只改本地 `liveOrigin` 画框，松手才落盘；这和属性面板滑杆的既有做法一致。

拖四角缩放另有一条约束：**对角固定，只改宽度、高度按素材比例推**。宽度取「被拖角到锚点的水平距离」，但必须按方向算而不是取 `abs`——鼠标越过锚点继续拖时，`abs` 会把负距离翻成正的，画中画会「反向放大」，越拖越大。上界按锚点到画幅边缘的剩余空间算，所以拖到边就停，不会先撑出画面再被 clamp 拽回来（那样会看到画中画跳一下）。九宫格模式下拖角会自动转成自由位置——「对角不动」这件事九宫格表达不了。

顺手修了一个老问题：预览合成以前固定 `1280×720`，竖屏 / 方形项目的预览比例是错的，画中画落位也跟着错。现在预览按项目画幅比例等比缩到最长边 1280 以内，预览台画框也跟着项目比例走。

### 自动闪避为什么写成关键帧

AVFoundation 没有内建的 sidechain 压缩，做不了「按另一条轨的电平实时压这条轨」。但音量关键帧这条路径是现成的——导出和预览走同一套 ramp，早就验证过。所以把「什么时候压、压多深」**提前算成一条包络**写进 `keyframes["volume"]`。

好处是它不是黑箱：生成完就是普通关键帧，可以在关键帧面板里逐点改时间、改数值、改缓动。

几个不那么显然的决定：

**只认同一条轨之外的音频片段当参考。** 视频轨自带的环境音不当人声用，否则音乐会被无关的声响压下去。

**两句之间太短的停顿不恢复。** 这里有个容易写错的地方：光判断「停顿 > 恢复时间 + 提前量」是不够的。间隔刚好比这个值长一点点时，音乐会抬起来 0.0x 秒又立刻压下去——听感上是抽搐，不是呼吸。所以还要加一个**最短平台期**（默认 0.3 秒）：抬起来维持不了这么久，就干脆不抬。

**淡入淡出要乘进包络。** 有关键帧时 `applyVolume` 会把淡入淡出交给关键帧表达，原来的 `fadeIn` / `fadeOut` 就不再单独生效。生成包络时把这段衰减乘进去，否则用户设的淡入会凭空消失。

**包络图填的是「曲线与原音量之间」的差值区，不是从底部铺起。** 从底部填充的话，抬起来的那段反而显得「被压了」，读图是反的。

### 素材丢了为什么值得单独做重连
时间线片段记的是**绝对路径**。文件在访达里挪个位置，片段就找不到素材了——`CompositionBuilder` 会把这一段直接跳过，成片里就是一段黑场，而导出本身不报错。

「删掉重新导入」能修好画面，但会连裁剪点、源入点、关键帧、转场、画中画参数、淡入淡出一起丢掉。所以重连只做一件事：**把路径换掉，其余字段一个不动**。实现上就是 `AssetRelinker.apply` 改 `TimelineItem.assetURL`，`MediaAsset.relink` 换 `url` 后重读元数据（id 不变，集合归属和选中状态都不会断）。

批量匹配只认**同名文件**（忽略大小写，APFS 本来就这样）。改名是猜不出来的——硬猜会把不相干的素材接上去，比找不到更糟：用户以为修好了，导出才发现全错。

一个容易漏的细节：素材库和时间线是两套引用，只改一边的话，素材库里那张卡还会显示「文件丢失」，或者反过来片段好了但库里是坏的。所以 `applyRelink` 两边一起改。

### 图标为什么要自己抠一遍

设计稿是白底的方形图。直接把 JPG 改名成 .icns 会得到「一个带白边的方块」：macOS 的 Dock / 访达会把整张图按原样摆进图标位，白色四角特别显眼。

所以构建前先过一遍 `make-icon`：

- **按非白像素找包围盒**，把画布收进图标本身。阈值不能取 246，JPEG 在边缘有一两行半透明白的过渡像素，判太松会把它当内容，成品顶上就留一道白线（这个 bug 真的出过，最后靠采样像素才定位到）。
- **再往里收 1.2%**，把源图圆角外侧的抗锯齿白边切掉。
- **按 macOS 图标网格缩进到 80.5%** 并切圆角（半径 = 内容边长 × 0.2237）。系统图标位四周是留白的，满铺反而比别人的图标大一圈。
- 最后 `sips` 出 10 个尺寸、`iconutil` 打包成 .icns。

### 闪避为什么可以拿字幕当参考

自动闪避要的是「什么时候有人在说话」。有两条路能拿到这个信息：

- **分析配音的波形**：20 ms 窗口算 RMS，低于阈值当静音。它不依赖字幕，但会被呼吸声、键盘声、空调底噪骗；配音轨不在时间线上（比如声音长在视频里）就没法用。
- **读字幕的时间**：字幕本来就是按发音对齐的，边界比静音检测更贴；而且纯算术，打开面板就有结果，字幕改了重新打开就跟着变。

所以面板上做成了「参考来源」两选一，默认仍走波形分析（不依赖字幕）。两个细节：

**只认 `.subtitle`，不认 `.text`。** 文字图层可能是标题卡，那段时间说话人往往没在说，拿它压音乐没道理。

**合并间隔用 `effectiveHoldGap`。** 面板上显示的「N 段」和真正生成的包络必须是同一套合并规则（恢复 + 再压 + 最短平台期），否则会出现「写着 3 段、导出却是 2 段」的对不上。

### 淡入淡出的手柄为什么要跟渲染器对齐上限

合成器里淡入是 `min(fadeIn, 时长 × 0.5)`：单侧最多吃片段的一半。属性面板原来的滑杆给到 2 秒，于是在 2 秒的片段上拖到 1.8 秒，画面其实只淡 1 秒——用户以为设了 1.8，导出却不是。手柄这次把上限算成 `min(时长 × 0.5, 时长 - 另一侧 - 0.02)`，滑杆也换成同一个上限，拖到哪儿就是哪儿。

吸附取 0.05 秒，小于 0.06 秒直接归零。归零这一条是必须的：否则拖回角落会留下 0.03 秒的斜坡，肉眼看不出来，但导出的第一帧不是全黑，「淡入」永远关不干净。

**拖拽起点取按下时的快照，位移每帧从 0 重算**，而不是拿当前值累加。像素换算成秒之后还要吸附到网格，累加就会一格一格地漂——手抖一下往回拖，数值回不到原处。

**手柄为什么会变虚。** 有两种情况淡入淡出不生效：片段已经有关键帧（`applyVolume` / 不透明度那一路会把整段交给关键帧），或者入场转场生效（只有 `plan.inTransition <= 0` 才铺淡入 ramp）。这时拖手柄画面不会有任何变化，所以手柄变虚、包络线画成虚线，悬停提示直接写「此刻不生效」。不这么做的话，用户只会觉得软件坏了。

**手柄和裁剪手柄抢位置。** 两者都在片段边缘，所以淡入手柄在 0 秒时往里让 6pt，并且压在片段上边缘、让开文字那一行：抓上边缘调淡入，抓中间还是裁剪。
